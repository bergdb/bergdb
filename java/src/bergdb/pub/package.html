Together with pub.util, this package forms the public BergDB API, "Pub". The package is used to store String and byte[] values by key, and Java objects, experimental in 2026.3.

Experimental in 2026.3, with known faults: a value that is neither a String nor a byte[] (a put of an object at a key, a get into another class), and the user indexes (Database.indexBuilder() and deleteIndex(), Connection.useIndex() and usePrimary(), and the interfaces IndexBuilder, UseIndexBuilder and UsePrimaryBuilder; Database.PRIMARY, StartupInfo.getStartupJobs(), and the exceptions of these parts). They may change in a later release (bergdb 018-01, D6). The rest of the Pub API, with the puts, gets and deletes of String and byte[] values, is not experimental.

Strings

Every string that BergDB stores is Unicode text: a sequence of Unicode scalar values, stored as well-formed UTF-8 (RFC 3629). It is a rule of BergDB's stream, the same in every language that writes or reads a database, not a detail of Java. It holds for every string: a key, a String value, each string in an object (a field's value, an array's element, at any depth, and a field's name), and an index name.

A put refuses a string that cannot be stored so, with IllegalArgumentException, before anything is written. In Java that is a String with a lone surrogate: a char of U+D800 to U+DFFF that is not part of a surrogate pair (a high surrogate followed by a low one), such as a String cut between the two chars of a pair, or "\ud800" decoded from JSON. The reason: UTF-8 cannot hold a lone surrogate, so the string read back would differ from the one put, in Java and in every other language, and BergDB does not change data silently. A call that takes a key, a get too, refuses a key with one in the same way.

A reader may rely on the rule: a string in the database is well-formed UTF-8, and a string put reads back equal, in any language.

Data that is not text, such as a String that may hold a lone surrogate, is stored as data: as a byte[] value, or in an object as a byte[] or a char[] field; a char[] keeps any chars and reads back exactly. Or the application repairs such a String before the put, for example with U+FFFD in place of each lone surrogate.

Depends on: common, nanotest, pub.util, pubimp. Only test code (the @Nano methods) uses nanotest. Factory uses pubimp to create a DatabaseBuilder: the circular package dependency pub -> pubimp -> pub is by design. Time also uses pubimp's TimeResolver.
