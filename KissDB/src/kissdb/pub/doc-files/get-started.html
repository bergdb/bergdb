Get started...

...with the Pub API of KissDB. It should be fun and simple to store objects and hopefully the Pub API won't bother you too much once you get a hang of it.

The code examples are also available in the kissdb.demo package in the KissDB distribution.

Store an object

The code below creates a new database in directory demo-db and stores the adam object to it. Then it reads back the object and prints the name field. Yes, it really is that simple :-). No query language, no special annotations, no interfaces, no xml settings - just code.

Java version

Include kissdb.jar in your Java project and run this code:

package demo; import kissdb.pub.*; class Person { public String name; public Person() {}; public Person(String name) { this.name = name; } } public class GetStarted1 { public static void main(String[] args) throws java.io.IOException { Person adam = new Person("Adam"); Database db = Factory.database().dir("demo-db").start(); Connection c = db.connection(); c.w().set("/p.obj", adam).execute(); Person p = c.get("/p.obj", Person.class); System.out.println(p.name); db.sync(); } }

C# version

Include the dll files in the dotnet/ directory of the KissDB download in your C# project. Then run this code:

using System; using kissdb.pub; namespace demo { class Person { public string name; public Person() {} public Person(String name) { this.name = name; } } class GetStarted1 { public static void Main(string[] args) { Person adam = new Person("Adam"); Database db = Factory.database().dir("db-GetStarted1").start(); Connection c = db.connection(); c.w().set("/p.obj", adam).execute(); Person p = c.get("/p.obj", Person.class); System.out.println(p.name); db.sync(); } } }

As you can see, the Java code and C# code is nearly identical. KissDB was designed to work well for both Java and .NET languages. Note that a cast is required, (Person), in C# while it can be omitted in Java. Also note that in C#, Java's .class suffix cannot be used. Instead use the typeof operator.

Languages

KissDB should be possible to use from any Java or .NET language which include: Java, Scala, Clojure, Groovy, JRuby, Jython, Rhino, C#, F#, VB.NET and more. KissDB is developed using Java source code and converted to a .NET library using IKVM (www.ikvm.net, thank you Jeroen Frijters!). The documentation for KissDB, the Pub API and code examples mostly assumes Java. However, I hope the docs should not be too hairy for a developer working with another language.

I gladly receive information on how it is to use KissDB from other languages than Java and C#.

Comments

The simple example above can used to store more complex objects. Java classes with field types: boolean, int, long, double, byte[] (or arrays of those types) are best suited for storing with KissDB, but the other primitive types work too.

Fields that are not static and not transient will be stored including private fields.

The class of objects to store should have an empty constructor.

Store two objects in a transaction

This example, adds a bit of code to store both adam and eve in the database.

package demo; import kissdb.pub.*; public class GetStarted2 { public static void main(String[] args) throws java.io.IOException { Person adam = new Person("Adam"); Person eve = new Person("Eve"); Database db = Factory.database().dir("db-GetStarted2").start(); Connection c = db.connection(); c.w().set("/genesis/a.obj", adam) .set("/genesis/e.obj", eve).execute(); System.out.println(c.get("/genesis/a.obj", Person.class).name); System.out.println(c.get("/genesis/e.obj", Person.class).name); db.sync(); } }

Both objects are stored in one ACID transaction. Another thread reading from the database will always see none or both objects. This is comparable to the highest SQL isolation level: serializable. Using KissDB, you will never ever have to deal with phantom reads, non-repeatable reads, dirty reads. Readers will always see a consistent state of the data. Yet, the performance of KissDB does not suffer. The database has been optimized for serializable ACID transactions using performant optimistic concurrency and fast append-only storage.

Iterate objects

The code below iterates the objects stored in the previous example.

package demo; import kissdb.pub.*; public class GetStarted3 { public static void main(String[] args) throws java.io.IOException { Database db = Factory.database().dir("db-GetStarted2").start(); Connection c = db.connection(); for (Person p : c.usePrimary(Person.class).dir("/genesis/").objects()) { System.out.println(p.name); } System.out.println("Backward:"); for (Person p : c.usePrimary(Person.class).dir("/genesis/").backward().objects()) { System.out.println(p.name); } System.out.println("Start at c:"); for (Person p : c.usePrimary(Person.class).dir("/genesis/").startAt("c").objects()) { System.out.println(p.name); } } }

This example iterates the objects stored with GetStarted2; forward, backward and then forward starting from "c".

Note that all keys start with "/". KissDB objects are stored using string keys that form a hierarchy - this is much inspired by a Unix filesystem; thus the beginning "/" for the absolute path to an object.

An RW transaction

This example shows how a payment is made in an RW transaction. An RW transaction is a transaction that both reads and writes to the database and the writes are dependent on the values from the reads.

package demo; import kissdb.pub.*; class Account { String key; long balance; Account() {} Account(String key, long balance) { this.key = key; this.balance = balance; } public String toString() { return key + ": " + balance; } } public class GetStarted4 { public static void main(String[] args) throws java.io.IOException { Database db = Factory.database().dir("db-GetStarted4").start(); Connection c = db.connection(); Account a0 = c.get("/accounts/0.obj", Account.class); Account a1 = c.get("/accounts/1.obj", Account.class); // Creates accounts if they do not exist. if (a0 == null) { a0 = new Account("/accounts/0.obj", 100); c.w().set(a0).execute(); } if (a1 == null) { a1 = new Account("/accounts/1.obj", 100); c.w().set(a1).execute(); } // Performs a payment if there is enough money. final long amount = 30; c.rw(new Action() { public void run(RwEnvironment env) { Account acc0 = env.get("/accounts/0.obj", Account.class); Account acc1 = env.get("/accounts/1.obj", Account.class); if (acc0.balance < amount) { throw new IllegalStateException( "Not enough money on: " + acc0); } acc0.balance -= amount; acc1.balance += amount; env.set(acc0); env.set(acc1); } }).execute().waitForD2(); // Lists accounts for (Account a : c.usePrimary(Account.class).objects()) { System.out.println(a); } } }

Run the code several times to until the not-enough-money exception is thrown.

An RW transaction is run by providing an Action for the database to execute. The action must always yield the same result (same data written database objects) for a certain input (objects read from the database). The run method may execute more then once if there are many concurrent users of the database. This is due to the STM (software transactional memory) approach taken by KissDB to achieve performance ACID transactions.

The example demonstrates the use of a key field in the class to store the database keys.
