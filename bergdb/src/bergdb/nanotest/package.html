This package is the implementation of a very small unit test framework. It is designed with BergDB in mind, but it is for general use.

Depends on: nothing. The package is self-contained, only depends on Java 1.5.

Properties of Nanotest

* Suitable for self-testing after deployment.
* Small. In code size.
* Code to be tested need not be dependent on Nanotest. Just use convention "public static void testXxx()".
* A simple test runner for console output included.
* Supports unit tests, longer-running functional tests and also performance tests.
* Test should be possible to group. For example into "unit", "functional", 
  "perf". Testing is started by selecting a set of test groups to run and a set of classes/methods.
* Tests should be able to report back arbitrary key-value pairs.
* A test is successful if it does not throw an exception.

Issues:

  all our environments? GCJ, IKVM, ..?

Without both reflection and annotations, this will be too ugly. 
Lets use reflection and annotations so we can develop something simple,
but still descent.

-- Annotation --
We use the name @T. We avoid JUnit's "@Test" to allow a method to run as
both a nano test and a JUnit test.
One parameter: a space-separated list of groups to which the test belongs.

-- No annotation? --
A "static void" method without parameters that has a name that starts with 
"test" is assumed to be a test method.
It will be run by the test runner even though it has no annotation. 
This way, the class to be tested can be completely independent of Nanotest.
These test methods always belong to the "unit" group and only that group.
