stream-format.txt
=================

This document is partial documentation for the BergDB stream format.
The authoritative documentation for the details is the code.
See classes: MetaBlock, StoredTrans, StoredTopNode, StoredKeyNode, StoredValueNode.

Before release 2015.4, there has been no effort to support compatibility of 
stored data between BergDB releases. That is, can a database created with BergDB 
Release A be read by a later Release B? Can it be used immediately, or is a 
conversion required?


Version Numbers
===============

There are several stream format version numbers.


Meta Block Version
------------------

The meta block format version is the version for the format of
the overall stream with the meta blocks and surrounding space for transactions.
The meta block version is not changed if the format for encoding transaction or
nodes will change.

Independent of the meta format version, we can assume the follow header
for meta blocks:

    Offset  Size    Description
    0       4       The bytes 'b', 'e', 'r', 'g'.
    4       2       Meta block format version. Range [133, 2^16-1].

Actually, we even limit assumption to only assume that bytes 4..5 
contain the version. Once the version is known, further assumptions can 
be made. Little-endian first byte order is used.

We also assume that there is a meta block in the stream at every stream 
position, n x 200000, where n is a non-negative integer.

The current version has meta blocks of size 128. The version is assumed
to correspond to the releaseInt of the BergDB release that introduced the
version.

See class MetaBlock for the authoritative specification of the current
version. Also see class RecoverableStream.


Trans Version
-------------

The transation format version is stored in the header of each
transaction in the stream. The code in StoredTrans.Serializer.serialize() is the 
definite definition of the format.

Independent of trans format version, we can assume a the following header:

    Offset  Size    Description
    0       4       The total byte size of the transaction. Range: [5, 2^31-1].
    4       1       Trans format version. One byte, range: [0, 127].

Little-endian-first byte order is used. The total byte size of the 
transaction does not include any meta block bytes that could possibly 
be interspersed within the transaction.

See class StoredTrans for the authoritative specification of the current 
version of the format.


Node Versions
-------------

Top nodes, key nodes and value nodes all have independent stream format
version numbers. See code in StoredTopNode, StoredKeyNode, StoredValueNode.

Independent of version number and node type, all nodes have the 
following header.

    Offset  Size    Description
    
    0       4       size - The total byte size of the node including this 
                        header. Range: [6, 2^31-1].
    4       1       node type - The node type. Must be 10 for a top node,
                        20 for a key node and 30 or 40 for a value node.
                        40 is used for a delete value node.
    5       1       version - Node format version. Independent version for
                        top nodes, key nodes and value nodes.

Little-endian-first byte order is used.

See classes StoredTopNode, StoredKeyNode, and StoredValueNode for the
authoritative specicification of the current serialization format.


Releases
========

This section has a list of BergDB releases and the stream version numbers in them.

* Meta = Version in stream metablock, see MetaBlock.
* Trans = Version in header of each transaction, see StoredTrans.
* Top = Version in header of a top node, see StoredTopNode.
* Key = Version in header of key node, see StoredKeyNode.
* Value = Version in header of value node, see StoredValueNode.

"Write" is the version numbers used when transactions are written to stream
and "Read" are the version numbers that can be read with the BergDB 
software of the particular release.
