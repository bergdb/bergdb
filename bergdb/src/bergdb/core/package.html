With support from other packages, this package implements the Core Layer. The Db class is the main class of the package.

Depends on: common, nanotest, stream, storage.

For BergDB developers

Exceptions

Methods in DB class should have documented exceptions for illegal parameter values. [throw new IllegalArgumentException...]. More "internal" methods, private, package private, or those never expected to be called by a Core Layer user, may have more lax parameter checking. Or use assertions, or throw Error/Bug when parameters are illegal. The input is expected to be correct for these methods.

Synch notes

When documentation says that Write Access (RA) is required to call a method it means that the calling thread must hold the monitor lock "DB.writeLock" to be allowed to run the method. This may not be enforced, the user of a class is responsible to make sure this is the case.

When Read Access (RA) is required for calling a method, there is little required when it comes to concurrency. Multiple concurrent readers are allowed. The implementation of a method requiring Read Access of the calling thread may assume the call stack contains a call to DB.get() or DB.getMany(). This means that the code [synchronized(DB.readSynch) {}] has been called recently.
